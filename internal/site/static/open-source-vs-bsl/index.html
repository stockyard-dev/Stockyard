Is Stockyard open source?

Stockyard is source-available under the Business Source License 1.1. The code is public, you can read and audit it, but it is not open source in the OSI-approved sense. Here is exactly what that means for you.

What you can do

  • Download, install, and run Stockyard for your own use
  • Self-host it on your own servers for your own applications
  • Use it in production for your company or your clients' projects
  • Read the entire source code on GitHub
  • Audit the security, cryptography, and data handling yourself
  • Fork the code for internal modifications
  • Build applications and services that use Stockyard as infrastructure
  • Use it commercially as long as you are not reselling it as a hosted service

What you cannot do

  • Offer Stockyard itself as a managed or hosted service to third parties
  • Resell Stockyard as a competing product
  • Take the source and launch a hosted "Stockyard-as-a-Service" offering

The restriction is focused on one scenario: using the source to offer a competing hosted service. For the full terms, read the LICENSE file in the repository. This page is a summary, not legal advice.

Why BSL and not MIT or Apache 2.0

The short answer: sustainability. Stockyard is built and maintained by one person. An MIT or Apache license would allow a well-funded company to take the source, host it as a managed service, and compete directly without contributing anything back. BSL prevents that specific scenario while keeping the source open for everyone else.

This is the same license used by MariaDB, CockroachDB, Sentry, and HashiCorp (for some products). It is a known quantity in the industry, not an exotic or custom license.

What BSL 1.1 actually says

BSL 1.1 has a built-in conversion clause. After a specified period (typically 4 years from each release), the code automatically converts to a permissive open-source license. This means every version of Stockyard will eventually become fully open source. The BSL is a time-limited restriction, not a permanent one.

The full license text is in the LICENSE file in the GitHub repository.

How this compares to competitors

LiteLLM: the proxy is Apache 2.0, but the enterprise features are proprietary. You get the open-source proxy, but advanced features require a paid license.

Langfuse: MIT-licensed core, fully open source. Langfuse Cloud is a managed offering on top of the open-source project.

Helicone and Portkey: managed SaaS products. The source is not available for self-hosting (Portkey has a limited open-source gateway).

Stockyard's approach is different: the entire platform is source-available, including the features that other products gate behind enterprise tiers. The only restriction is on how you can redistribute it.

If the license is a dealbreaker

Some organizations have policies that prohibit non-OSI-approved licenses. If that is your situation, Stockyard may not be the right choice today. LiteLLM's proxy (Apache 2.0) or Langfuse (MIT) may be better fits for your licensing requirements. We would rather be honest about this than have you discover a licensing conflict later.
