Full REST API

Every operation in Silo is available through a JSON REST API. No SDK required — use curl, fetch, or any HTTP client.

  • GET /api/partitions — list all partitions with optional search and filter query parameters
  • POST /api/partitions — create a new partition record
  • GET /api/partitions/{id} — retrieve a single partition by ID
  • PUT /api/partitions/{id} — update an existing partition
  • DELETE /api/partitions/{id} — remove a partition
  • GET /api/stats — aggregated statistics with status breakdown
  • GET /api/health — health check endpoint for monitoring
Why self-host your data isolation and partitioning layer

SaaS tools hold your data hostage. Export formats are incomplete, migrations are painful, and pricing changes whenever the vendor feels like it. Silo stores everything in SQLite on your own server. Your data is a file you control, back up, and query directly.

Real-world usage

A freelance consultant keeps Silo running on a home server. Client partitions stay on local disk, which simplifies the privacy section of every contract. The search endpoint powers a custom dashboard built with a static site generator. Total infrastructure cost: the electricity to run a Raspberry Pi.

Under the hood

Install Silo with the one-line shell script or download the binary directly from GitHub. Run it, open /ui, and start creating partitions. The SQLite database lives in a single file under the data directory. To migrate to a new server, copy the binary and the data directory. That is the entire migration procedure.

Endpoints
  • GET /api/partitions — List all partitions. Supports ?q=keyword for search and ?status=value for filtering
  • POST /api/partitions — Create a new partition. Send JSON with at least name
  • GET /api/partitions/{id} — Fetch one partition by ID
  • PUT /api/partitions/{id} — Update fields on an existing partition
  • DELETE /api/partitions/{id} — Remove a partition
  • GET /api/stats — Returns total count and breakdown by status
  • GET /api/health — Returns {"status":"ok"} for uptime monitoring
