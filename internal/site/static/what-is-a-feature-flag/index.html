What is a feature flag?

A feature flag is a way to turn features on or off in your application without deploying new code. Here is everything you need to know.

The explanation

A feature flag (also called a feature toggle) is a conditional check in your code that controls whether a feature is active. Instead of deploying new code to enable a feature, you flip a flag.

The simplest version is a boolean: if the flag is on, show the new checkout flow. If it is off, show the old one. More advanced flags support percentage rollouts (show it to 10% of users), user targeting (show it only to beta testers), and multivariate values (show variant A to half, variant B to the other half).

The power of flags is that they decouple deployment from release. You deploy the code with the flag set to off. When you are ready, you flip the flag. If something breaks, you flip it back. No rollback, no redeploy, no downtime.

// Check the flag before showing the feature
if (featureFlags.isEnabled('new-checkout')) {
  showNewCheckout();
} else {
  showOldCheckout();
}
When to use them

Common use cases.

  • Staged rollouts — deploy to 5% of users, monitor, then increase
  • Kill switches — wrap risky code so on-call can disable it without a deploy
  • Beta programs — show new features only to users who opted in
  • A/B testing — split traffic between variants to measure which performs better
  • Trunk-based development — merge incomplete features behind flags instead of long-lived branches
Do not wrap everything in a flag. Flags add complexity and technical debt. Use them for features that need gradual rollout or a kill switch. Remove flags once a feature is fully launched and stable.
How it works

A feature flag service stores flag definitions (name, type, default value, targeting rules). Your application calls the service to evaluate a flag for a given user. The service returns the value. Advanced services cache evaluations locally so the flag check does not add latency to every request.

Targeting rules determine which users see which value. Common targeting: by user ID (specific users), by percentage (random 10%), by property (users in the US), or by segment (beta testers group).

FAQ
What is the difference between a feature flag and a config file?
A config file requires a restart or redeploy to change. A feature flag can be toggled in real time without touching the application. Flags also support user-level targeting that config files cannot.
Do feature flags slow down my app?
Minimal impact. Local evaluation (cached flags) adds microseconds. Remote evaluation (API call per check) adds a few milliseconds. Most flag services cache aggressively.
How do I clean up old flags?
Remove flags once a feature is fully launched and stable. Most teams add a cleanup date when creating a flag. Stale flags are technical debt.
