How to Self-Host Analytics with Headcount

5 minutes · No Docker · No external dependencies

This guide walks through setting up private web analytics on your own server. By the end, you will have a running analytics dashboard that tracks page views, unique visitors, referrers, and custom events — without sending any data to Google or any third party.

Prerequisites

A Linux server (Ubuntu 22.04+, Debian, or any distro with systemd). Any VPS with 512MB RAM is enough. Headcount adds negligible load — it typically uses less than 20MB of memory.

Step 1: Install Headcount

Download the binary with the install script. This places a single file in your current directory.

curl -fsSL https://stockyard.dev/headcount/install.sh | sh

Verify the binary runs:

./headcount --version

Step 2: Create a systemd service

For production use, run Headcount as a systemd service so it starts on boot and restarts on failure.

sudo mkdir -p /opt/headcount /var/lib/headcount
sudo cp headcount /opt/headcount/
sudo tee /etc/systemd/system/headcount.service > /dev/null <<'EOF'
[Unit]
Description=Headcount Analytics
After=network.target

[Service]
Type=simple
ExecStart=/opt/headcount/headcount
Environment=PORT=8690
Environment=DATA_DIR=/var/lib/headcount
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable headcount
sudo systemctl start headcount

Check that it is running:

curl http://localhost:8690/api/health
# Expected: {"status":"ok","events":0}

Step 3: Set up a reverse proxy

Put Headcount behind nginx with HTTPS so the tracking snippet works on your production site.

sudo tee /etc/nginx/sites-available/analytics > /dev/null <<'EOF'
server {
    listen 443 ssl;
    server_name analytics.yourdomain.com;

    ssl_certificate /etc/letsencrypt/live/analytics.yourdomain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/analytics.yourdomain.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8690;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
EOF

sudo ln -sf /etc/nginx/sites-available/analytics /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

Step 4: Add the tracking snippet

Add a single line to your website's HTML. Replace the URL with your Headcount instance.

<script defer src="https://analytics.yourdomain.com/js/headcount.js"></script>

Alternatively, track events server-side by POSTing directly to the API:

curl -X POST https://analytics.yourdomain.com/api/events \
  -H "Content-Type: application/json" \
  -d '{"name":"pageview","path":"/pricing","referrer":"https://google.com"}'

Step 5: Verify and view your dashboard

Open https://analytics.yourdomain.com/ui in your browser. You should see the Headcount dashboard with your first page view recorded. The dashboard shows unique visitors, top pages, referral sources, and session counts with daily rollups.

Step 6: Backups

All data lives in a single SQLite file. Set up a daily backup with a cron job:

# Add to crontab: daily backup at 2 AM
0 2 * * * sqlite3 /var/lib/headcount/headcount.db ".backup /var/backups/headcount-$(date +\%Y\%m\%d).db"

To restore from a backup, stop Headcount, copy the backup file to the data directory, and restart. That is the entire disaster recovery procedure.

What you have now

A private analytics server that tracks every page view without sending data to Google. No cookies, no consent banners, no sampled data. The SQLite database will handle millions of events before you need to think about scaling. Total infrastructure cost: whatever your VPS costs per month.
