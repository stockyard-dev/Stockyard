How to Self-Host Error Tracking

Set up Seismograph as a self-hosted Sentry alternative. Capture exceptions, deduplicate errors, and track resolution — all on your own server.

This guide sets up Seismograph — a self-hosted error tracking tool that captures exceptions, deduplicates repeated errors, and groups them for analysis. Unlike Sentry, it runs as a single binary with no Docker, Postgres, Kafka, or Clickhouse.

Prerequisites

A Linux server with shell access. Seismograph uses minimal resources — it runs comfortably on a $5/mo VPS alongside your application.

Step 1: Install and start

curl -fsSL https://stockyard.dev/seismograph/install.sh | sh
sudo mv seismograph /usr/local/bin/
sudo mkdir -p /var/lib/seismograph

Create a systemd service (same pattern as any Stockyard tool):

cat <<EOF | sudo tee /etc/systemd/system/seismograph.service
[Unit]
Description=Seismograph Error Tracking
After=network.target
[Service]
Type=simple
ExecStart=/usr/local/bin/seismograph
Environment=PORT=9700
Environment=DATA_DIR=/var/lib/seismograph
Restart=always
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now seismograph

Step 2: Send your first error

Send an error event from any language using a simple HTTP POST:

# From your application's error handler
curl -X POST http://localhost:9700/api/events \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "NullPointerException in PaymentService.process",
    "source": "payment-api",
    "severity": "error",
    "payload": "{"stack_trace": "...", "request_id": "abc-123"}"
  }'

In Python, wrap this in your exception handler:

import requests, traceback, json

def report_error(e, context=None):
    requests.post("http://localhost:9700/api/events", json={
        "name": f"{type(e).__name__}: {str(e)}",
        "source": "my-app",
        "severity": "error",
        "payload": json.dumps({
            "traceback": traceback.format_exc(),
            "context": context or {}
        })
    })

Step 3: Monitor and resolve

Open /ui to see your error dashboard. Errors are grouped by name and sorted by frequency. The stats endpoint at /api/stats returns counts by severity — wire this into Grafana or your alerting system to get notified when error rates spike.

Search by keyword to find related errors across services. Filter by severity to focus on critical issues. The API supports all operations, so you can build custom dashboards or pipe error data into your incident management workflow.

Backup and maintenance

Back up /var/lib/seismograph/seismograph.db daily. The database grows with your error volume — at typical rates (hundreds of errors per day), expect single-digit megabytes per month. For high-volume applications, use the retention API to prune old events periodically.
