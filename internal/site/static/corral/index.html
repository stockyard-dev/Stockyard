Quickstart

Up in 30 seconds.

Download the binary, run it, and you have a live webhook endpoint.

Install
curl -fsSL https://stockyard.dev/corral/install.sh | sh
Run
DATA_DIR=./data corral

  Stockyard Corral dev
  Webhook relay:  http://localhost:8760/hook/{endpoint_id}
  API:            http://localhost:8760/api
  Live stream:    http://localhost:8760/api/endpoints/{id}/stream
Create an endpoint and get your capture URL
curl -s -X POST http://localhost:8760/api/endpoints \
  -H 'Content-Type: application/json' \
  -d '{"name":"stripe-dev"}'

# {"endpoint":{"id":"ep_a1b2c3d4","name":"stripe-dev",...},
#  "hook_url":"http://localhost:8760/hook/ep_a1b2c3d4"}

Point Stripe (or anything else) at http://localhost:8760/hook/ep_a1b2c3d4. Every request is captured, stored, and available to inspect or replay.

Use cases

Three things developers use this for.

Local webhook development
Run Corral locally instead of exposing your laptop with Ngrok. Inspect every webhook in detail, replay failed ones without re-triggering the source.
Debug webhook failures in staging
Something is dropping webhooks in staging but you can't reproduce it. Corral captures everything so you can see exactly what arrived and replay it against the fixed version.
Fan out one webhook to multiple services
One Stripe event needs to hit your billing service, your Slack notifier, and your analytics pipeline. Corral's forward rules send it to all three, with retry on failure.
Why not heavier tools

Webhook.site is fine until you need replay. Ngrok requires an account.

Webhook.site is great for a quick look at a payload. But it doesn't persist, it doesn't replay, and it doesn't run on your server. Ngrok solves the tunneling problem but you're sending traffic through someone else's infrastructure.

Corral runs in your environment. Webhooks never leave your network. You get a full inspection UI, replay to any target, auto-forwarding rules with retry, and a live SSE stream for real-time monitoring. Single binary, no Docker required, ~9MB.

Scope

When Corral is all you need.

Corral is the right tool if your problem is specifically about webhooks: receiving them, inspecting them, replaying them, or forwarding them. It does one thing and does it well.

If you're receiving webhooks from payment processors, CI systems, or third-party SaaS tools, Corral handles all of it. The free tier covers 1,000 events/month, which is enough for most development workflows. Pro removes that limit for $0.99/month.

FAQ
Does Corral require Docker or a database?
No. Single Go binary, embedded SQLite. Run it anywhere you can run a binary.
Can I run it on a server, not just locally?
Yes. Set PORT and DATA_DIR environment variables. Put it behind a reverse proxy if you want TLS. A Dockerfile is included in the repo.
How does the free tier work?
The free tier is unlimited for self-hosted use up to 1,000 stored events. Old events are cleaned up automatically based on the RETENTION_DAYS setting (default 30 days). Pro removes the event limit.
What's the license?
Apache 2.0. Free to use, modify, and deploy. No usage restrictions.
Is this related to Stockyard?
Corral is a focused standalone tool from the Stockyard family. If you're building LLM applications, Stockyard is the full platform that includes LLM proxying, tracing, cost control, and much more.
