What Are Webhooks?

HTTP callbacks that push event notifications to your application in real time.

How webhooks work

A webhook is an HTTP POST request that a service sends to your application when something happens. When a customer pays through Stripe, Stripe sends a POST request to a URL you configured — your webhook endpoint. The request body contains the event data: payment amount, customer ID, timestamp. Your application receives this request and acts on it — updating the order status, sending a confirmation email, provisioning access.

Webhooks are the inverse of polling. Instead of your application asking "did anything happen?" every 30 seconds, the service tells your application "something happened" the moment it occurs. This is more efficient (no wasted requests) and faster (no 30-second delay).

The testing problem

Webhooks are difficult to test during development because your local machine is not accessible from the internet. Stripe cannot send a POST request to localhost:3000. Developers traditionally solve this with tools like ngrok (which exposes your local port to the internet) or webhook.site (which captures webhooks in a cloud service).

Both approaches send your webhook payloads through a third party. For payment webhooks containing transaction amounts and customer data, this creates a data residency concern. A self-hosted webhook capture tool avoids this.

Self-hosted webhook testing

Corral is a self-hosted webhook relay. It captures incoming webhooks, lets you inspect the full payload (headers, body, query string), and replay them to test your handler. Run it on your server, point your webhook source at it, and debug without sending data through a third party.

curl -fsSL https://stockyard.dev/corral/install.sh | sh
stockyard-corral
# Dashboard: http://localhost:8760/ui
