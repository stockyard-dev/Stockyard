Use Case

One gateway for the whole team.

Your team of 3-15 developers needs LLM API access. Instead of everyone managing their own keys and providers, route everything through one gateway with shared controls and per-developer visibility.

The team problem

Every developer on the team has their own OpenAI key. Nobody knows what the total spend is. There is no shared caching, so three developers testing the same prompt pay three times. When someone leaves, their key is still active. When the bill spikes, nobody knows who caused it.

A shared gateway fixes this. One set of provider keys managed centrally. Per-developer usage visible in the dashboard. Shared caching so the team does not pay for duplicate work. Rate limits so one runaway script does not drain the budget.

How teams typically set it up

Install once. One developer installs Stockyard on a shared server or VM. The team points their OPENAI_BASE_URL at the gateway. Provider keys are configured centrally.

Model aliasing. Map "fast" and "smart" to specific models. The team uses logical names in their code, and the gateway handles routing. When you want to switch models, change one alias instead of updating every developer's config.

Cost visibility. The dashboard shows total spend, spend per model, and request volume. When the bill looks wrong, you can find the specific requests that caused it.

Caching. Enable caching on the gateway and every developer benefits. The same prompt sent by three different people hits the provider once and returns cached results for the other two.

What the setup looks like

One developer sets up the gateway. Everyone else changes one environment variable:

# On the shared server (once) curl -fsSL stockyard.dev/install.sh | sh export OPENAI_API_KEY=sk-your-team-key export ANTHROPIC_API_KEY=sk-ant-your-team-key export STOCKYARD_ADMIN_KEY=sy_admin_team_secret stockyard # On every developer's machine (one line) export OPENAI_BASE_URL=http://gateway.internal:7749/v1

From that point on, every LLM request from every developer routes through the gateway. The dashboard at gateway.internal:7749/ui shows who is sending what, which models are being used, and how much it is costing.
