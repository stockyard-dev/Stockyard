Use Case

Four levers to control LLM costs.

Spending caps, response caching, model aliasing, and rate limiting. All built into one proxy, all configurable at runtime, all available on the free tier.

The levers

Most LLM cost problems come down to four things you can control at the proxy layer. Stockyard gives you all four as middleware modules. Each one is a single API call to enable.

Four levers to control cost

Each one is a middleware module you can enable at runtime. No restart, no redeploy.

1. Spending caps. Set a daily or monthly dollar limit. When the cap is hit, requests return a 429 instead of billing more tokens. You choose whether to hard-stop or switch to a cheaper model.

curl -X PUT http://localhost:4200/api/proxy/modules/costcap \ -H "X-Admin-Key: $STOCKYARD_ADMIN_KEY" \ -H "Content-Type: application/json" \ -d '{"enabled": true, "config": {"daily_limit_usd": 10.0}}'

2. Response caching. Identical or semantically similar prompts return cached responses instead of making a new API call. During development, this alone can substantially reduce costs by eliminating duplicate requests.

curl -X PUT http://localhost:4200/api/proxy/modules/cachelayer \ -H "X-Admin-Key: $STOCKYARD_ADMIN_KEY" \ -H "Content-Type: application/json" \ -d '{"enabled": true, "config": {"ttl": 3600}}'

3. Model aliasing. Route "smart" requests to GPT-4o and "fast" requests to GPT-4o-mini. When you realize 70% of your traffic does not need the expensive model, change one alias instead of rewriting your app.

curl -X PUT http://localhost:4200/api/proxy/aliases \ -H "X-Admin-Key: $STOCKYARD_ADMIN_KEY" \ -H "Content-Type: application/json" \ -d '{"alias": "fast", "model": "gpt-4o-mini"}'

4. Rate limiting. Cap requests per minute per key or per model. This prevents runaway loops and abusive users from draining your budget before you notice.

curl -X PUT http://localhost:4200/api/proxy/modules/rateshield \ -H "X-Admin-Key: $STOCKYARD_ADMIN_KEY" \ -H "Content-Type: application/json" \ -d '{"enabled": true, "config": {"rpm": 60}}'

See where the money goes

Stockyard tracks cost per request automatically. Every API call records the model used, tokens consumed, and estimated cost in USD. You can query cost data through the API or browse it in the web console at /ui.

# Get cost summary for the last 24 hours curl http://localhost:4200/api/observe/costs/summary \ -H "X-Admin-Key: $STOCKYARD_ADMIN_KEY" # Response { "period": "24h", "total_usd": 4.23, "by_model": { "gpt-4o": 3.41, "gpt-4o-mini": 0.82 }, "requests": 847, "cached": 312 }

In this example, 312 out of 847 requests were served from cache. That is 37% of requests that did not cost anything. The cost breakdown by model shows exactly where to look if you want to optimize further.

No external services required

All four cost levers, plus the cost tracking dashboard, run inside the Stockyard binary. No Redis for caching. No separate analytics service for cost data. No external rate limiter. Everything is stored in one SQLite file and managed through one API.
