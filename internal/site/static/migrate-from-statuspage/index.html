Migrate from Statuspage.io to Paddock

Self-hosted replacement. Single binary. 10 minutes setup.

Time: 10 minutes Saves: $79/mo Binary: ~12MB Dependencies: none

Before you start

What transfers Component names, subscriber email list (manual import via API)
What does not transfer Incident history, custom CSS themes, Atlassian integration. Paddock starts fresh. If you need historical data, export it from Statuspage.io before cancelling.

Step 1: Install Paddock

curl -fsSL stockyard.dev/paddock/install.sh | sh
stockyard-paddock

The binary starts an HTTP server with a dashboard at http://localhost:8760/ui and a REST API at http://localhost:8760/api.

Step 2: Configure

Open the dashboard and set up your configuration. Paddock stores everything in a SQLite file in the current directory. No external database to provision.

For production, set a data directory and run as a systemd service:

DATA_DIR=/var/lib/paddock stockyard-paddock

See the full Paddock documentation for configuration options.

Step 3: Verify

Open the dashboard at localhost:PORT/ui. Add your first component. Create a test incident. Check the public status page renders at localhost:PORT.

✓ If you see data in the dashboard, Paddock is working.

Step 4: Switch traffic

Point your application to Paddock instead of Statuspage.io. Update any webhook URLs, SDK configurations, or DNS records. Run both in parallel for a few days if you want to compare.

Once you are confident, cancel your Statuspage.io subscription. Your data stays on your server regardless of what happens to the Statuspage.io account.

The honest tradeoff

Statuspage.io charges $79/mo for the Startup plan. Paddock is a single binary you run on a separate $5 VPS so your status page stays up even when your main infrastructure goes down. The tradeoff: no native Atlassian integration and no managed email delivery for subscriber notifications (bring your own SMTP).
