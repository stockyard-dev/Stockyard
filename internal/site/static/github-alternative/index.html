Self-Hosted GitHub Alternative

Host your Git repositories on your own infrastructure. No per-seat fees, no code scanning by AI training pipelines, no dependency on GitHub's uptime.

Why self-host your Git repos

GitHub is the default for open source and most private repositories. For many teams, it is the right choice. The reasons to self-host are specific: your code cannot leave your network (defense, healthcare, finance), you do not want your code used as AI training data (GitHub Copilot trains on hosted code), you need to reduce vendor concentration (if GitHub goes down, your CI/CD, code review, and deployment all stop), or you are in a jurisdiction where data sovereignty matters.

Self-hosted Git is not about GitHub being bad. It is about controlling where your source code — the most valuable intellectual property most companies own — physically resides.

Githost — Git repository management in one binary

Githost is a self-hosted repository manager that runs as a single Go binary. Create repositories, manage visibility (public/private), track metadata, and serve your codebase from your own server. No Docker, no Postgres, no Java runtime.

curl -fsSL https://stockyard.dev/githost/install.sh | sh
PORT=9700 ./githost

The dashboard shows all repositories with descriptions, default branches, visibility settings, and size. The API supports repository creation, listing, and management programmatically.

For a more complete GitHub replacement

If you need pull requests, issue tracking, CI/CD runners, and a web-based code browser, Gitea is the most mature self-hosted GitHub alternative. It requires more infrastructure than Githost (database server, more RAM), but it covers nearly all of GitHub's functionality. Githost is for teams that need repository management and metadata tracking without the full forge experience.

Pair with other Stockyard tools

Githost handles repository management. For the other workflows GitHub provides, pair it with Bounty (issue tracking), Crucible (code review), Pipeline (CI/CD orchestration), and Ironworks (build artifact storage). Each runs as an independent binary — install the ones you need, skip the ones you do not.
