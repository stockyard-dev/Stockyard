Migrate from LaunchDarkly to Salt Lick

Self-hosted replacement. Single binary. 15 minutes setup.

Time: 15 minutes Saves: $50/mo Binary: ~12MB Dependencies: none

Before you start

What transfers Flag names and targeting rules (manual recreation via API)
What does not transfer Experimentation data, audit history, LaunchDarkly SDK integrations. Salt Lick starts fresh. If you need historical data, export it from LaunchDarkly before cancelling.

Step 1: Install Salt Lick

curl -fsSL stockyard.dev/saltlick/install.sh | sh
stockyard-saltlick

The binary starts an HTTP server with a dashboard at http://localhost:8790/ui and a REST API at http://localhost:8790/api.

Step 2: Configure

Open the dashboard and set up your configuration. Salt Lick stores everything in a SQLite file in the current directory. No external database to provision.

For production, set a data directory and run as a systemd service:

DATA_DIR=/var/lib/saltlick stockyard-saltlick

See the full Salt Lick documentation for configuration options.

Step 3: Verify

Create a boolean flag via the dashboard. Query it via the API. Toggle it and verify your app sees the change.

✓ If you see data in the dashboard, Salt Lick is working.

Step 4: Switch traffic

Point your application to Salt Lick instead of LaunchDarkly. Update any webhook URLs, SDK configurations, or DNS records. Run both in parallel for a few days if you want to compare.

Once you are confident, cancel your LaunchDarkly subscription. Your data stays on your server regardless of what happens to the LaunchDarkly account.

The honest tradeoff

LaunchDarkly charges per seat ($10/seat/mo minimum). Salt Lick has no per-seat pricing. The tradeoff: Salt Lick does not have LaunchDarkly's SDKs for every language, streaming flag updates, or built-in experimentation. If you need boolean/percentage flags with a REST API and no seat limits, it fits. If you need real-time streaming SDKs in 25 languages, LaunchDarkly is more complete.
