The LiteLLM supply chain attack and what it means

In March 2026, LiteLLM's PyPI package was compromised. Here is what happened and how to think about LLM proxy security.

LiteLLM is a popular Python-based LLM proxy that routes requests across multiple providers. In March 2026, the project was hit by a supply chain attack via PyPI — the Python package registry. Malicious code was injected into a dependency, which meant anyone who ran pip install litellm during the window of compromise potentially ran the attacker's code.

This is not a criticism of the LiteLLM team. Supply chain attacks are a systemic problem in package manager ecosystems. PyPI, npm, and RubyGems have all been targets. The LiteLLM team responded quickly once the attack was discovered.

Why this matters for LLM proxies

An LLM proxy is a particularly high-value target for supply chain attacks. It sees every API key, every prompt, every response. If an attacker compromises the proxy, they can exfiltrate API keys (OpenAI, Anthropic), read sensitive prompts, modify responses, or route traffic through their own servers.

Python-based proxies inherit the full PyPI dependency tree. LiteLLM's requirements.txt pulls in dozens of packages, each with their own dependencies. Any one of those dependencies is a potential attack vector.

The single-binary approach

A single compiled Go binary has no runtime dependencies. There is no package manager to compromise, no dependency tree to audit, no pip install that pulls code from the internet. The binary you download is the entire application — what you see is what you run.

This is not a theoretical advantage. The LiteLLM attack demonstrated exactly why runtime dependency management is a risk for security-sensitive infrastructure like LLM proxies.

The Stockyard LLM proxy ships as a single Go binary (~25MB). It compiles all 76 middleware modules, 16 provider adapters, and the web dashboard into one file. No pip, no npm, no external packages at runtime.

What to do

If you use LiteLLM, audit your installation and update to the latest patched version. If you are evaluating LLM proxies, consider the supply chain attack surface as part of your decision. A compiled binary eliminates an entire category of risk.
