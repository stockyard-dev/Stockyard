Helicone Was Acquired — What Happens Now

Helicone was acquired by Mintlify in March 2026 and entered maintenance mode. If you relied on it for LLM observability, here is the full picture of what happened, what it means, and where to go next.

What happened

Mintlify, the documentation platform, acquired Helicone in March 2026. The Helicone product entered maintenance mode — existing deployments continue to work, but active development stopped. No new features, no new provider integrations, and bug fixes are limited to critical security patches.

For teams that built their LLM cost tracking and observability around Helicone, this creates a concrete problem. Maintenance mode is not the same as end-of-life, but it means the tool will fall further behind as providers release new models, change pricing, and update API formats. A cost tracker that does not know about next month's new model is a cost tracker that underreports.

What Helicone did well

Helicone was genuinely good at its job. The core workflow — drop in a proxy URL, see cost per request in a clean dashboard — was the simplest LLM observability setup available. No SDK to install, no code changes beyond swapping the base URL. It tracked cost, latency, token usage, and request volume across OpenAI, Anthropic, and other providers. The dashboard showed spend trends over time, per-model breakdowns, and individual request traces.

The things teams will miss most: the simplicity of setup (change one URL), the accuracy of cost calculations (they tracked pricing changes across providers), and the clean UI that made it easy to spot cost anomalies without configuring dashboards or writing queries.

Your options

Langfuse — full observability platform

Best for: Teams that need tracing, evaluation, prompt management, and cost tracking in one platform. Langfuse is the most feature-complete open-source LLM observability tool available. The self-hosted version requires Docker and Postgres. The cloud version starts at $59/month. If you need everything Helicone did plus prompt versioning, A/B testing, and evaluation pipelines, Langfuse is the closest full replacement.

The tradeoff: Langfuse is more complex to self-host than Helicone was. The Docker + Postgres requirement means you are running a real database cluster, not a single binary. For teams with infrastructure experience, this is fine. For teams that liked Helicone specifically because it was simple, the operational overhead is a meaningful step up.

Trough — self-hosted cost tracking

Best for: Teams whose primary Helicone use case was cost tracking. Trough is a self-hosted LLM cost tracker that runs as a single Go binary with embedded SQLite. No Docker, no Postgres, no Redis. Install it in 30 seconds:

curl -fsSL https://stockyard.dev/trough/install.sh | sh
DATA_DIR=./data stockyard-trough
# Dashboard: http://localhost:9700/ui

Trough tracks per-request cost, latency, and token usage. The dashboard shows spend over time, per-model breakdowns, and anomaly detection. The API exposes all data programmatically for custom dashboards and alerting.

The tradeoff: Trough focuses specifically on cost tracking. It does not do prompt management, evaluation, or tracing beyond what is needed for cost attribution. If cost monitoring was your primary Helicone use case, Trough covers it at $7.99/month. If you needed Helicone's full observability features, Trough alone is not a complete replacement.

Migrating from Helicone

If your application used Helicone's proxy approach (swapping the base URL), migration is a URL change. Replace Helicone's proxy URL with Trough's or Stockyard's. Your application code does not change — the proxy handles everything transparently.

If you used Helicone's SDK, you will need to remove the SDK dependency and switch to the proxy approach. This is typically a smaller change than it sounds — remove the Helicone import, set the base URL to the proxy, and delete the Helicone initialization code. The proxy captures everything the SDK was reporting.

Historical data from Helicone does not migrate — there is no export-to-import path. Your new tool starts fresh. If you need historical cost data for reporting, export it from Helicone before their maintenance period ends.

The LiteLLM supply chain attack

Worth noting in this context: LiteLLM also had a significant security incident in March 2026. A PyPI supply chain attack compromised the package, potentially exposing API keys and request data for users who installed the affected version. If you were evaluating LiteLLM as a Helicone alternative, this incident is relevant to your risk assessment.

Self-hosted Go binaries like Trough and Stockyard avoid this attack surface entirely. There is no package manager in the dependency chain — you download a compiled binary and run it. No pip, no npm, no transitive dependencies that could be compromised. This is not a theoretical advantage; it is the difference between a supply chain attack affecting you and not affecting you.

The broader trend

Helicone's acquisition reflects a pattern in the LLM tooling market: standalone observability tools being absorbed by larger platforms. The economics are straightforward — observability alone is hard to monetize at scale, so these tools get acquired for their technology and user base rather than growing independently.

For teams choosing LLM tools, this pattern argues for self-hosted options where possible. A managed service can be acquired, sunset, or repriced at any time. A binary on your server runs until you decide to stop it. The Helicone acquisition is not unusual — it is the expected outcome for most venture-funded developer tools that do not reach escape velocity.
