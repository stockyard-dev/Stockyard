Why single-binary tools are taking over

Download a file. Run it. You are done. No Docker, no database, no config.

Something shifted in the last two years. Tools that used to require Docker Compose files with seven containers now ship as a single file you download and run. The database is embedded. The web server is built in. The dashboard is included. There is nothing to install, nothing to configure, and nothing to break.

This is not new technology — Go and SQLite have been around for over a decade. What is new is that developers are choosing simplicity over features. A tool that does one thing well and installs in 30 seconds is beating the all-in-one platform that requires a weekend of setup.

What makes a good single-binary tool

The pattern is consistent across every good single-binary tool:

One file to download. No runtime dependencies — not Go, not Node, not Python. The binary is the entire application. Set one environment variable for the data directory, run the binary, and a dashboard appears at localhost on a known port.

Embedded storage via SQLite. Not Postgres, not MySQL, not Redis. SQLite handles tens of thousands of requests per second, supports concurrent readers, and stores everything in a single file you can back up with cp.

An HTTP API for everything. No custom protocols, no gRPC requirement, no client library needed. Any language that can make HTTP requests can use the tool.

The tradeoff

Single-binary tools are not for massive scale. SQLite is single-writer. A single binary runs on one machine. If you need to process millions of events per second across a cluster, you need the distributed system.

But most teams do not need that. Most status pages serve a few hundred requests per minute. Most feature flag services evaluate a few thousand flags per second. Most error trackers process a few hundred errors per hour. A single binary with SQLite handles all of this comfortably.

The question is not "can this scale to Netflix?" The question is "does this solve my problem today, and can I install it in 30 seconds?"

Examples

Self-hosted Sentry requires Kafka, Clickhouse, Postgres, and Redis. Seismograph is one binary that captures errors, groups them, and sends alerts. 12MB.

Self-hosted Discourse requires Docker, Postgres, Redis, and 2GB+ RAM. Watering Hole is one binary that runs a community forum. 12MB.

Airbyte self-hosted is a 7-container Docker Compose stack. Wrangler is one binary for ETL pipelines. 12MB.

The pattern repeats across 164+ tools at stockyard.dev/tools. Each one is 12-14MB, embedded SQLite, zero dependencies.
