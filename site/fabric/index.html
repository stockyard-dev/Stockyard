Deployment Engine

Fabric — Declarative Deployment Engine

Define your AI infrastructure as manifests. Deploy with a single command. Let self-healing keep everything running.

How It Works

Manifest-Based Deployment

Fabric treats your deployment configuration as code. Write a JSON or YAML manifest describing your desired state — models, routes, middleware, scaling rules — and Fabric makes it so.

  • Declarative: Describe what you want, not how to get there
  • Idempotent: Apply the same manifest repeatedly with identical results
  • Version-controlled: Every deployment is recorded with full rollback history

Reliability

Self-Healing Infrastructure

Fabric continuously reconciles actual state with desired state. If a node goes down, routes break, or middleware fails, Fabric detects the drift and corrects it — automatically.

  • Health checks every 10 seconds
  • Automatic failover to healthy replicas
  • Drift detection and reconciliation
  • Alerting via webhooks when intervention is needed

History

Version History & Rollback

Every deployment creates an immutable snapshot. Roll back to any previous version instantly. Compare manifests side-by-side to understand what changed.

API

API Endpoints

POST /api/v1/fabric/apply Apply a manifest
GET /api/v1/fabric/status Current deployment status
GET /api/v1/fabric/history Deployment version history
POST /api/v1/fabric/rollback Rollback to a previous version
GET /api/v1/fabric/diff Compare two manifest versions

Example

Example Manifest

// fabric-manifest.json { "apiVersion": "fabric/v1", "kind": "Deployment", "metadata": { "name": "production-gateway", "namespace": "default" }, "spec": { "replicas": 3, "provider": "openai", "model": "gpt-4o", "middleware": [ "rate-limiter", "cost-tracker", "audit-logger" ], "scaling": { "minReplicas": 2, "maxReplicas": 10, "targetUtilization": 0.75 } } }
