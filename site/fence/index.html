Quickstart

Up in 60 seconds.

Install, run, create a vault, store a key. Team members resolve it with their token.

Install
curl -fsSL https://stockyard.dev/fence/install.sh | sh
Run
FENCE_ADMIN_KEY=secret \
FENCE_ENCRYPTION_KEY=$(openssl rand -hex 32) \
fence

  Stockyard Fence dev
  API:      http://localhost:8770/api
  Resolve:  http://localhost:8770/api/resolve/{key_name}
Store a key and issue a token to a team member
# Create vault
curl -s -X POST http://localhost:8770/api/vaults \
  -H 'Authorization: Bearer secret' \
  -d '{"name":"production"}'

# Store a key
curl -s -X POST http://localhost:8770/api/vaults/{vault_id}/keys \
  -H 'Authorization: Bearer secret' \
  -d '{"name":"openai","value":"sk-...","provider":"openai"}'

# Issue a token to alice
curl -s -X POST http://localhost:8770/api/vaults/{vault_id}/tokens \
  -H 'Authorization: Bearer secret' \
  -d '{"member_id":"{member_id}","name":"alice-token"}'

# Alice resolves the key at runtime
curl -s http://localhost:8770/api/resolve/openai \
  -H 'Authorization: Bearer fence_...'
# Returns: {"key":"openai","value":"sk-..."}
Use cases

Three things developers use this for.

Replace .env file sharing
Every dev on the team has a copy of production keys in their .env. One laptop compromise exposes everything. Fence issues each dev a token, keys stay encrypted on the server.
Rotate keys without app restarts
Rotate a key in Fence and every app that resolves it at runtime gets the new value on the next request. No redeploys, no coordinating restarts.
Audit who accessed what and when
Compliance audit asks which employees had access to the Stripe API key last quarter. Fence has a log of every resolution: who, when, from where.
Why not heavier tools

HashiCorp Vault is powerful but complex. Fence is 9MB.

Vault is the right answer when you have hundreds of services, dynamic secrets, and a dedicated platform team. For most teams, the problem is simpler: stop sharing API keys in chat and give people a way to access them that leaves a trail. Fence does that without requiring you to learn HCL or run a cluster.

AES-256-GCM encryption at rest, scoped tokens per team member, instant revocation, audit log. Single binary, embedded SQLite, zero infrastructure dependencies.

Scope

When Fence is all you need.

Fence is the right tool when the problem is shared API key management for a small to medium team. It handles encrypted storage, per-member access tokens, rotation, and audit logging. It doesn't do dynamic secrets, PKI, or Kubernetes integration.

The free tier covers 10 keys and 2 team members. Pro removes those limits for $4.99/month.

FAQ
Are keys stored encrypted?
Yes. AES-256-GCM encryption at rest. Set FENCE_ENCRYPTION_KEY to a 32-byte hex key. If not set, it derives from the admin key (not recommended for production).
What happens when I revoke a token?
Revocation is instant. The next resolve request with that token returns 401. The underlying key is unaffected — other tokens still work.
Can I scope a token to a specific key?
Yes. Set key_id when issuing a token and that token can only resolve that specific key, not the whole vault.
