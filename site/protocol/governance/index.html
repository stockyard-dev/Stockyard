Protocol Specification

AI Governance Protocol

An open specification for routing, executing, and verifying AI governance requests across distributed providers.

Overview

Protocol Overview

The Stockyard AI Governance Protocol (SAIP) defines a standard way for clients, proxies, and governance providers to communicate. It builds on existing standards like OpenAI's API format while adding layers for routing, verification, and auditability.

  • Provider-agnostic: One request format, any backend
  • Verifiable: Cryptographic attestation of governance results
  • Observable: Built-in telemetry and cost tracking
  • Composable: Middleware pipeline for request/response transformation

Layers

Protocol Layers

Layer 1
Transport
HTTP/2 and WebSocket connections with TLS 1.3. Supports streaming via Server-Sent Events.
Layer 2
Authentication
API key, JWT, and mutual TLS authentication. Scoped permissions per key.
Layer 3
Routing
Model-based, cost-based, and latency-based routing with fallback chains.
Layer 4
Middleware
Ordered pipeline of request/response transformations: rate limiting, caching, PII redaction, logging.
Layer 5
Execution
Provider-specific adapters translate the unified format to each backend's native API.
Layer 6
Verification
Cryptographic hash of request + response for audit trails and dispute resolution.

Request Format

Request Envelope

Every governance request is wrapped in a protocol envelope that carries routing hints, middleware directives, and tracing metadata.

// SAIP Request Envelope { "protocol": "saip/v1", "request_id": "req_abc123", "routing": { "strategy": "lowest-cost", "fallback": ["openai", "anthropic", "mesh"], "max_latency_ms": 5000 }, "middleware": ["pii-redact", "cache", "audit"], "payload": { "model": "gpt-4o", "messages": [ { "role": "user", "content": "Summarize this document." } ], "max_tokens": 1024 }, "trace": { "parent_id": "span_xyz", "tags": { "team": "platform" } } }
