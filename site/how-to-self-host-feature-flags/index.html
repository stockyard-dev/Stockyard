How to Self-Host Feature Flags

Set up Salt Lick as a self-hosted LaunchDarkly alternative. Toggle features without redeploying, no per-seat pricing, no SDK required.

This guide sets up Salt Lick — a self-hosted feature flag service that lets you toggle features without redeploying. No LaunchDarkly SDK, no per-seat pricing, no vendor dependency. Your application checks a flag by making a single HTTP request.

Step 1: Install

curl -fsSL https://stockyard.dev/saltlick/install.sh | sh
PORT=9700 DATA_DIR=/var/lib/saltlick ./saltlick

Step 2: Create your first flag

# Create a feature flag
curl -X POST http://localhost:9700/api/flags \
  -H 'Content-Type: application/json' \
  -d '{"name": "new-checkout", "enabled": false, "description": "New checkout flow"}'

Step 3: Check flags in your application

No SDK needed. A single HTTP GET returns the flag state:

# In your application code
response = requests.get("http://localhost:9700/api/flags")
flags = {f["name"]: f["enabled"] for f in response.json()["flags"]}

if flags.get("new-checkout"):
    render_new_checkout()
else:
    render_old_checkout()

The request adds single-digit milliseconds of latency. For performance-critical paths, cache the flag values for 30 seconds and refresh in the background.

Step 4: Toggle without deploying

Enable the flag through the dashboard at /ui or via the API:

# Enable the new checkout for everyone
curl -X PUT http://localhost:9700/api/flags/{id} \
  -H 'Content-Type: application/json' \
  -d '{"enabled": true}'

The change takes effect immediately. No deployment, no restart, no cache invalidation. To roll back, set enabled back to false.

Step 5: Production setup

For production, run Salt Lick as a systemd service behind your reverse proxy. The flag data is a single SQLite file — back it up daily. The entire flag service typically uses less than 10MB of disk and negligible CPU.

For teams with multiple environments, run one Salt Lick instance per environment (staging, production). Each instance gets its own data directory and port. Flag state is independent per instance, so you can test flags in staging without affecting production.
